## 5. Content model, in brief (full detail in `03-content-standards.md`)

- **Lesson:** front matter (id like `j5-l3.2`, title, `concepts`, `objectives` with ids, `prerequisites`, `estimated_minutes`, `sources`, `features` with Java version labels, optional `resources`) and required sections in this order: Before you start (with a quick check in a `<details>`), Explanation, Worked examples, (optional Predict, then run), Where this is used, Common mistakes (each `:::mistake{id=MCnn}` must be a registered misconception), Practice (`::exercise{id=...}` lines), optional Version notes, Further reading, How you'll be assessed. **Every objective must be assessed by an exercise.** Source citations look like `[I56]` and must be rows in `sources.md`.
- **Exercise types:** `predict` (a program and its expected output), `parsons`, `write`, `debug`, `modify`, `explain` (a rubric with three levels and sample answers). A test is exactly one of: a method test (`args`/`expect`), an I/O test (`stdin`/`stdout_*`), or a source test (`source_contains` / `source_not_contains`, whitespace-collapsed).
- **Grading:** the learner's file is compiled and run in a separate JVM with time (2 s per case), memory and output limits. It is **not a sandbox**. A reflective harness calls the learner's top-level methods and compares scalars, arrays and `List`s of boxed types or `String`s only (no `Map`, `Set`, `Optional` or objects as arguments or returns). To test classes, the starter carries a **driver method** that uses the learner's class and returns a string, and the tests call the driver. Compact source files do **not** enforce `private` between classes in one file, so use source tests when encapsulation is the point.
- **The validator** (`./scripts/validate-content.sh`, 1 to 2 minutes) enforces, among other things: every reference solution passes; every starter fails (and compiles unless `starter_compiles: false`); every `wrong/` solution fails; at least 3 visible and 5 hidden tests; hints; verified sources; a 3-level rubric for explain exercises; and project rules. It also **rejects the words "placeholder" and "TODO" in lesson text**; rephrase them. It has caught real mistakes many times, for example wrong solutions that accidentally passed. Treat each error as information, not an obstacle.
- **Mastery:** levels 0 to 5, computed from an append-only attempt log. Each concept lists `required_evidence` using the types IMPL, EXPL, MIST, DEBUG, MOD, XFER. Only list evidence types that your exercises can actually produce.
- **Projects:** Category B and C projects need requirements, constraints, acceptance criteria, a rubric of at least 3 criteria and a design-note prompt. Wrong solutions are named `<milestoneId>-<name>.java`. A project is a single `Main.java`. Milestone tests can include source tests.

## 8. Rules you must follow (learned the hard way)

5. **Use performance exercises carefully:** large inputs from a driver, a 2-second limit, and a read-counting wrapper where timing would be unreliable. Avoid anything nondeterministic.
