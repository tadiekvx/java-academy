## Before you start

You should know how to write a small program that prints lines with `IO.println` and `IO.print` ([Your first program](j1-l1.1)).

**Quick check.** What does this print?

```java
void main() {
    IO.print("Hello, ");
    IO.println("world");
}
```

<details><summary>Show the answer</summary>

`Hello, world` on one line. `IO.print` stays on the same line, and `IO.println` finishes it.

</details>

## Explanation

Every programmer makes errors, all day, every day: beginners and people with twenty years' experience alike. The difference is that experienced programmers have learned to **read** error messages and use them. An error message isn't a telling-off. It's Java pointing at the problem and telling you what it noticed.

### Compile errors

Remember the two steps from the last lesson: Java first **compiles** your program (checks it's written correctly), then **runs** it. If the check finds a problem, you get a **compile error** and nothing runs at all.

Here's a program with a mistake in it. Can you spot it before you run it?

```java
void main() {
    IO.println("Hello")
    IO.println("World");
}
```

Java's message for it looks like this:

```
Main.java:2: error: ';' expected
    IO.println("Hello")
                       ^
1 error
```

Read it piece by piece:

| Part | Meaning |
|---|---|
| `Main.java` | The file with the problem. |
| `:2` | The **line number**: line 2. |
| `error: ';' expected` | **What Java noticed**: it expected a semicolon. |
| the copied line, and `^` | The line again, with a `^` marking the exact spot. |

In this course's editor, the same error appears as **Error, line 2: ';' expected**, and line 2 gets a red wavy underline.

Notice that the `^` points just **after** `("Hello")`. That's where the semicolon should go. Java reports the spot where it realised something was missing.

### The errors you'll meet most

These are the messages you'll see most often as a beginner. Each one, with what usually causes it:

| Message | Usual cause |
|---|---|
| `';' expected` | A statement is missing its semicolon at the end. |
| `cannot find symbol` | A name is misspelt or has the wrong capitals, such as `IO.printn`, `io.println` or `IO.printIn`. Java then lists the name it couldn't find under `symbol:`. |
| `unclosed string literal` | A string is missing its closing `"`. |
| `reached end of file while parsing` | A `{` was never closed: a `}` is missing, usually at the end. |

For example, misspelling `println` gives:

```
Main.java:2: error: cannot find symbol
    IO.printn("Hello");
      ^
  symbol:   method printn(String)
  location: class IO
```

The `symbol:` line tells you exactly which name Java couldn't find: `printn`.

### Fix the first error first

One small mistake can confuse Java enough to produce several error messages, and the later ones are often just knock-on effects of the first. So:

1. Read the **first** error only.
2. Go to its line and fix it.
3. Run again, and repeat with whatever error is now first.

It's tempting to fix everything at once, but working one at a time is faster in the end, because the knock-on errors disappear by themselves.

### Runtime errors

Some problems can't be found by checking how the program is written. They only show up when the program **runs**. This program compiles fine:

```java
void main() {
    IO.println("Sharing 12 sweets between 0 friends...");
    IO.println(12 / 0);
}
```

When it runs, the first line prints, and then the program stops with this (you'll run it yourself in the last debugging exercise):

```
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Main.main(Main.java:3)
```

This is a **runtime error**, called an **exception** in Java. The program started, did the first statement, and crashed on line 3, because dividing by zero has no answer. You'll learn to read these messages fully in [Exceptions and stack traces](j1-l6.4). For now, know the difference:

| | Compile error | Runtime error |
|---|---|---|
| When | Before the program starts | While the program is running |
| Does anything run? | No | Yes, everything up to the crash |
| Typical cause | Something written incorrectly | Something impossible happening, like dividing by zero |

## Worked examples

### Example 1: one error

*Task: this program should print `Good morning` and then `Have a nice day`. It won't compile.*

```java
void main() {
    IO.println("Good morning);
    IO.println("Have a nice day");
}
```

**Step 1 — Find the line.** The error is `Main.java:2: error: unclosed string literal`, so the problem is on line 2.

**Step 2 — Read the message.** "Unclosed string literal" means a string doesn't end. The `^` points at the opening `"` of `"Good morning`.

**Step 3 — Look at that spot.** The text `"Good morning` never gets its closing `"`.

**Step 4 — Fix it and run again.** Add the missing quote: `IO.println("Good morning");`. It compiles and prints both lines.

### Example 2: several errors, one at a time

*Task: this program has three mistakes. Fix them in order.*

```java
void main() {
    IO.println("Step one")
    io.println("Step two");
    IO.printn("Step three");
}
```

**Step 1 — First error only:** `Main.java:2: error: ';' expected`. Add the semicolon at the end of line 2. Run again.

**Step 2 — The new first error.** This time Java reports two errors at once. Take the first: `Main.java:3: error: cannot find symbol`, with `symbol: variable io`. Java doesn't know any `io` with a lower-case i. It should be `IO`. Fix and run again.

**Step 3 — The new first error:** `Main.java:4: error: cannot find symbol`, with `symbol: method printn(String)`. The method is `println`. Fix and run again.

**Step 4 — It compiles.** Check the output really is what you wanted: `Step one`, `Step two`, `Step three`.

## Where this is used

- **Every working day.** Professional developers compile and run their code many times an hour, and reading the messages quickly is a core skill.
- **Code editors** underline errors as you type, using the same compiler messages you're learning to read here.
- **Searching for help.** Pasting the message text (like `reached end of file while parsing`) into a search engine is one of the most common things developers do. It works because the messages are always worded the same way.

## Common mistakes

### Looking at the wrong line

The `^` points where Java **noticed** the problem, which is sometimes just after the real mistake. A missing semicolon is reported at the end of the line it's missing from. A missing `}` is reported at the end of the file. If the line looks fine, check the line just before it.

### Fixing errors out of order

Reading the last error first often means chasing a problem that doesn't really exist: it was a knock-on effect of an earlier one. Start at the top.

### Thinking "it compiled" means "it works"

Compiling only proves the program is written correctly. It can still crash while running, or run and print the wrong thing. Always check the output.
