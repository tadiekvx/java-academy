## Explanation

Programs need to **remember** things: a score, a total so far, how many tries are left. They remember them in **variables**.

### A variable is a named box

A **variable** is a named place that holds one value of one type. You create one with a **declaration**:

```java
int score = 0;
```

Read it right to left: *put the value `0` into a new box called `score`, which can only hold `int`s.*

- `int` is the variable's type. It can never change.
- `score` is its name.
- `= 0` gives it its first value.

You can then use the name anywhere you'd use the value:

```java runnable
void main() {
    int score = 0;
    double price = 2.50;
    String player = "Sam";

    IO.println(score);
    IO.println(price);
    IO.println(player);
}
```

### `=` means "store", not "equals"

In maths, `x = 5` states a fact. In Java, `=` is an **instruction**: work out the value on the right, then **store** it in the variable on the left. That's why this line makes sense in Java, even though it would be nonsense in maths:

```java
score = score + 10;
```

Java works out the right-hand side first, using the **current** value of `score`, then stores the result back into `score`. If `score` was 0, it's now 10.

Because `=` means "store into the left", the two sides aren't interchangeable. `score = total;` copies `total` into `score`; `total = score;` does the opposite.

### A variable holds one value at a time

When you store a new value, the old one is **gone**. A variable doesn't remember its history:

```java runnable
void main() {
    int lives = 3;
    lives = 2;
    lives = 5;
    IO.println(lives);
}
```

This prints `5`. Only the latest value is kept.

Notice that `int` appears only once, when `lives` is first declared. After that you just use the name: writing `int lives = 2;` a second time would try to create a second variable with the same name, which is an error.

### Copying a value copies it *now*

```java runnable
void main() {
    int a = 5;
    int b = a;
    a = 10;
    IO.println(a);
    IO.println(b);
}
```

This prints `10`, then `5`. The line `int b = a;` copies the value **5** into `b` at that moment. It doesn't link `b` to `a`, so changing `a` afterwards doesn't touch `b`.

### Tracing: following the values line by line

To work out what a program does, **trace** it: make a table with a column for each variable, and fill in a row for each line as it runs.

```java
int x = 3;
int y = x * 2;
x = x + 1;
y = y - x;
```

| Line | `x` | `y` |
|---|---|---|
| `int x = 3;` | 3 | |
| `int y = x * 2;` | 3 | 6 |
| `x = x + 1;` | 4 | 6 |
| `y = y - x;` | 4 | 2 |

At the end, `x` is 4 and `y` is 2. Tracing feels slow at first, but it's the most reliable way to understand code, and research on how novices learn to program suggests that people who can trace accurately also find writing code easier.

### Names

Variable names can contain letters, digits and `_`, but can't start with a digit, and they're case-sensitive (`score` and `Score` are different). By convention, Java names start lower-case and capitalise each following word: `livesLeft`, `totalPrice`. This style is called **camelCase**. Choose names that say what the value means: `seconds` beats `s`, and `priceInPence` beats `p`.

### Using a variable before giving it a value

You can declare a variable without a value (`int score;`), but you can't **use** it until it has one. Java checks this when compiling:

```
error: variable score might not have been initialized
```

### `final`: a value that must not change

Put `final` in front of a declaration when the value should never change:

```java
final int maxLives = 3;
```

If any later line tries `maxLives = 5;`, the program doesn't compile (`cannot assign a value to final variable maxLives`). That protects you from changing it by accident.

### `var`: let Java work out the type

When the type is obvious from the value, you can write `var` instead of the type:

```java
var count = 0;      // an int, because 0 is an int
var name = "Ada";   // a String
```

The variable still has a fixed type, which Java works out from the first value, and it can't change later. `var` only saves typing. In this course we'll mostly write types out in full while you're learning them.

## Worked examples

### Example 1: a running total

*Task: a game awards 10 points, then 25, then takes away 5. Print the score after each change.*

**Step 1 — Create the variable with a starting value.** `int score = 0;`

**Step 2 — For each change, work out the new value from the old one,** and store it back: `score = score + 10;`

**Step 3 — Print after each step,** using `IO.print` for a label so the label and value share a line.

```java runnable
void main() {
    int score = 0;

    score = score + 10;
    IO.print("After the first award: ");
    IO.println(score);

    score = score + 25;
    IO.print("After the second award: ");
    IO.println(score);

    score = score - 5;
    IO.print("After the penalty: ");
    IO.println(score);
}
```

**Step 4 — Check with a trace.** 0 → 10 → 35 → 30. The output matches.

### Example 2: swapping two values

*Task: swap the values of `left` and `right`, so whatever was in `left` ends up in `right` and the other way round.*

**Step 1 — Try the obvious way, and trace it.**

```java
left = right;
right = left;
```

With `left = 1` and `right = 2`: the first line makes `left` 2, and the 1 is **gone**. The second line copies that 2 back into `right`. Both end up 2.

**Step 2 — Keep a copy before you overwrite it.** Use a third variable to hold `left`'s old value.

**Step 3 — Write it, and trace it.**

```java runnable
void main() {
    int left = 1;
    int right = 2;

    int saved = left;
    left = right;
    right = saved;

    IO.println(left);
    IO.println(right);
}
```

| Line | `left` | `right` | `saved` |
|---|---|---|---|
| start | 1 | 2 | |
| `int saved = left;` | 1 | 2 | 1 |
| `left = right;` | 2 | 2 | 1 |
| `right = saved;` | 2 | 1 | 1 |

It prints `2` then `1`.

## Where this is used

- **Games:** score, health, lives and position are all variables that change many times a second.
- **Shopping baskets:** the running total is updated every time an item is added or removed.
- **Fixed settings:** values like a maximum number of login attempts are marked `final`, so they can't be changed by accident halfway through a program.

## Common mistakes

:::mistake{id=MC01}
**Reading `=` as "equals".** `x = x + 1` isn't an impossible equation. It means *work out `x + 1`, then store it in `x`*. And `a = b` isn't the same as `b = a`: the value always flows from right to left.
:::

:::mistake{id=MC02}
**Expecting a variable to remember old values.** After `lives = 3; lives = 2;`, the 3 is gone for good. If you'll need an old value later, save it in another variable first, as in the swap example.
:::

:::mistake{id=MC03}
**Expecting copied variables to stay linked.** After `int b = a;`, changing `a` doesn't change `b`. The copy happens once, at that moment.
:::

## Version notes

`var` was added in **Java 10** (2018). You'll see it in modern code, but older code always writes the type out in full. Everything else in this lesson has worked the same way since Java 1.0.
