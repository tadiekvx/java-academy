## Explanation

Programs do arithmetic constantly: totals, averages, percentages, time conversions. Most of it behaves exactly as you'd expect from maths. One part doesn't, and it's behind a large share of beginner bugs: **dividing one whole number by another**. This lesson makes sure it never catches you out.

### The five arithmetic operators

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `+` | addition | `7 + 2` | `9` |
| `-` | subtraction | `7 - 2` | `5` |
| `*` | multiplication | `7 * 2` | `14` |
| `/` | division | `7 / 2` | `3` (not a typo, see below) |
| `%` | remainder | `7 % 2` | `1` |

### Which part is worked out first

Java follows the same order as maths:

1. Anything in **parentheses** first.
2. Then `*`, `/` and `%`.
3. Then `+` and `-`.

Operators at the same level are worked out **from left to right**. So `2 + 3 * 4` is `14` (the multiplication happens first), and `20 / 2 * 5` is `50`: Java divides first (`10`), then multiplies, because `/` comes first reading left to right. It does *not* work out `2 * 5` first.

When an expression could confuse a reader, add parentheses even if they aren't needed. `(20 / 2) * 5` means the same thing and nobody has to stop and think.

### Dividing two ints gives an int

When **both** sides of `/` are `int` values, Java does *integer division*: the answer is an `int`, and any fractional part is **thrown away**. It doesn't round to the nearest whole number. It cuts the fraction off.

- `7 / 2` is `3` (the 0.5 is discarded)
- `9 / 10` is `0` (0.9 is discarded, not rounded up to 1)
- `-7 / 2` is `-3` (the Java Language Specification says integer division "rounds toward 0", so a negative answer moves *up* towards zero, not down to −4)

This isn't a bug in Java. An `int` can only hold whole numbers, so the result of `int / int` has to be whole too.

### The remainder operator `%`

`%` gives what's **left over** after integer division. `7 / 2` is `3` with `1` left over, so `7 % 2` is `1`. Some more:

- `135 % 60` is `15` (135 minutes is 2 whole hours, with 15 minutes left over)
- `20 % 5` is `0` (nothing left over, because 5 divides 20 exactly)
- `4 % 10` is `4` (10 goes into 4 zero times, so all 4 are left over)

With negative numbers, the remainder takes the sign of the **left-hand** number: `-7 % 2` is `-1`. Division and remainder always fit together: `(a / b) * b + (a % b)` gets you back to `a`. For example, `(-7 / 2) * 2 + (-7 % 2)` is `-6 + -1`, which is `-7`.

### Getting an exact answer: bring in a `double`

If **either** side of a division is a `double`, Java converts the other side to `double` too and gives you a `double` answer with its fractional part:

- `7.0 / 2` is `3.5`
- `7 / 2.0` is `3.5`

With variables, you can't just add `.0`, so you *cast* one of them. Writing `(double)` in front of a value converts that value to a `double`:

```java
int total = 7;
int count = 2;
double average = (double) total / count; // 3.5
```

**Where you put the cast matters.** `(double) total / count` converts `total` *before* dividing, so the division happens with a double. `(double) (total / count)` divides first (integer division, giving `3`) and only then converts the `3` to `3.0`. That's too late, because the fraction has already gone.

Casting works the other way too: `(int) 3.99` is `3`. Converting a `double` to an `int` cuts off the fraction, just like integer division does.

### Dividing by zero

`7 / 0` stops your program with an error: `java.lang.ArithmeticException: / by zero`. You'll learn to read messages like this in [Exceptions and stack traces](j1-l6.4). `7.0 / 0` doesn't stop the program. It gives the special `double` value `Infinity`. Neither is usually what you want, so make sure a value can't be zero before you divide by it. You'll learn how in Module 3.

### A note on `double` precision

A `double` stores numbers in binary, so most decimal fractions are stored as a very close approximation. Try this:

```java runnable
void main() {
    IO.println(0.1 + 0.2);
}
```

It prints `0.30000000000000004`. This is normal for doubles in every mainstream language, and for most calculations the tiny error doesn't matter. It's also why the exercise tests in this course accept answers that are extremely close to the expected value, and why programs that handle money usually store whole pence as `int` rather than pounds as `double`. You'll do exactly that in the Parking Fee project.

## Worked examples

### Example 1: an exact average

*Task: two quiz scores are stored as `int`s. Work out their average exactly.*

**Step 1 — Decide the type of the answer.** An average of 7 and 8 is 7.5, so the answer must be a `double`.

**Step 2 — Check the types going into the division.** `first + second` is `int + int`, which is an `int`. Dividing that by the `int` `2` would be integer division, and the `.5` would be lost.

**Step 3 — Make the division happen with a double.** Divide by `2.0` instead of `2`.

**Step 4 — Test with a case that has a fraction.** Scores that add up to an even number (like 6 and 8) would work even with the bug, so they prove nothing. Use 7 and 8.

```java runnable
void main() {
    int first = 7;
    int second = 8;

    double wrong = (first + second) / 2;
    double right = (first + second) / 2.0;

    IO.println(wrong);
    IO.println(right);
}
```

This prints `7.0` and then `7.5`. Look at the first line closely. `wrong` is a `double` variable, but that doesn't help. `(first + second) / 2` is worked out as integer division first (`15 / 2` is `7`), and only *then* is the `7` stored as `7.0`. The type of the variable you store into doesn't change how the right-hand side is calculated.

### Example 2: splitting a quantity into units

*Task: a film lasts 135 minutes. Show it as whole hours and leftover minutes.*

**Step 1 — Identify the size of one unit.** One hour is 60 minutes.

**Step 2 — Whole units: divide.** `135 / 60` is `2`. Integer division throwing away the fraction is exactly what we want here.

**Step 3 — Leftover: take the remainder.** `135 % 60` is `15`.

**Step 4 — Check the edge cases.** 60 minutes should be 1 hour and 0 minutes, 59 minutes should be 0 hours and 59 minutes, and 0 should be 0 and 0.

```java runnable
void main() {
    int totalMinutes = 135;
    int hours = totalMinutes / 60;
    int minutes = totalMinutes % 60;

    IO.print("Hours: ");
    IO.println(hours);
    IO.print("Minutes: ");
    IO.println(minutes);
}
```

Change `135` to `60`, `59` and `0`, and run the program again each time to check Step 4.

### Example 3: rounding a division up

*Task: a coach holds 50 people. How many coaches are needed for 120 people?*

**Step 1 — Notice that integer division rounds down.** `120 / 50` is `2`, but 2 coaches only hold 100 people. We need to round *up* whenever there's anything left over.

**Step 2 — Use the "add one less than the divisor" pattern.** `(people + 49) / 50` adds 49 (one less than the coach size) before dividing.

**Step 3 — Check why it works, with a full and a partial load.**
- 100 people: `(100 + 49) / 50` is `149 / 50`, which is `2`. That's exactly full, so no extra coach. ✓
- 101 people: `(101 + 49) / 50` is `150 / 50`, which is `3`. The one extra person tips it into a third coach. ✓

Adding 49 can push any partial coach over the next multiple of 50. It can never push an exact multiple of 50 that far.

```java runnable
void main() {
    int people = 120;
    int seatsPerCoach = 50;
    int coaches = (people + seatsPerCoach - 1) / seatsPerCoach;
    IO.println(coaches);
}
```

This prints `3`.

## Where this is used

- **Time displays.** A video player that knows a clip is 125 seconds long works out the `2` and the `5` in `2:05` with `125 / 60` and `125 % 60`. Adding the leading zero is a separate formatting step.
- **Pagination.** A search page showing 10 results per page needs `(results + 9) / 10` pages, which is the round-up pattern from Example 3.
- **Money.** Payment systems store amounts as whole pence or cents in integer types to avoid the precision problem shown above. Splitting a £10.00 bill three ways is `1000 / 3` = 333p each, with `1000 % 3` = 1p left over that someone has to pay.
- **Packing and scheduling.** Boxes needed for an order, weeks and days until a deadline, and how many full teams you can make all use `/` and `%`.

## Common mistakes

:::mistake{id=MC04}
**Expecting integer division to keep the fraction.**

```java
double half = 1 / 2 * 10;   // 0.0, not 5.0
```

`1 / 2` is integer division, so it's `0`, and `0 * 10` is `0`. Fix: make the division use a double, e.g. `10 / 2.0`, or avoid the division entirely with `0.5 * 10`.

**Casting too late** is the same mistake in disguise:

```java
double average = (double) (total / count); // the fraction is already gone
double average = (double) total / count;   // correct: total becomes a double first
```
:::

### Expecting division to round to the nearest whole number

`9 / 10` is `0`, not `1`. Integer division always cuts off the fraction. When you need rounding up, use the pattern from Example 3.

### Forgetting the order of operations

`a + b / 2` divides only `b` by 2. To average `a` and `b`, write `(a + b) / 2.0`.

## Version notes

The arithmetic in this lesson has worked the same way since the first version of Java. Writing a program as just `void main() { … }` and printing with `IO.println` needs **Java 25** or newer (see [Your first program](j1-l1.1)). In older code and most online material you'll see the same arithmetic inside `public class Main { public static void main(String[] args) { … } }`, printed with `System.out.println`.
